# Colors

Color tokens have two jobs: primitive values form the palette, and semantic tokens describe how the interface uses color. Components should use semantic roles so themes can change without changing component styles.

<h2 id="color-layers">Color layers</h2>

The current primitive palette contains a blue scale, white, saffron, and a brand blue. Semantic tokens cover surfaces, text, borders, focus, brand, accent, and status roles. The palette is intentionally smaller than a utility-class color catalog; use semantic names for everyday component styling.

<h2 id="semantic-roles">Semantic roles</h2>

Choose a semantic role by what it means in the interface, not only by how its color looks. For example, use `--chakra-color-text-primary` for primary text and `--chakra-color-surface-canvas` for a page surface.

<h2 id="theme-colors">Theme colors</h2>

The system color scheme is the default. The dark theme remaps semantic variables while keeping their names stable. Set `data-theme="light"` or `data-theme="dark"` on a root element or subtree to select a theme explicitly.

<CodeBlock code={`<section
  data-theme="dark"
  style={{
    color: "var(--chakra-color-text-primary)",
    background: "var(--chakra-color-surface-canvas)",
  }}
>
  The semantic colors update with the theme.
</section>`} />

<h2 id="color-guidance">Usage guidance</h2>

- Use semantic color variables in component styles.
- Keep primitive palette values in theme definitions and token packages.
- Pair color with text, shape, or another cue when it communicates status.
- Check text and control contrast against the actual surface in each theme.
